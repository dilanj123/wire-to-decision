Original WIRE-028 benchmark synthesis:
- `proc_memwr` did not hang: the pass completed and Yosys advanced through PROC_CLEAN/OPT into FSM_EXTRACT.
- The source contains a clocked 8-lane ordered loop with blocking updates to parser state and several dynamically indexed byte arrays (`eth_q`, `ip_q`, `udp_q`, `mold_q`, `msg_q`). The old synthesis log reports `msg_q` replaced by a list of registers, then logs thousands of mux/control decisions before stopping in FSM_EXTRACT.
- The evidence points to the entire unrolled procedural state-update chain, with dynamic array writes as contributors; it does not isolate `msg_q` as the sole cause.

- Parser `proc` completes in 34.55 s (real), peak memory 669.59 MB; `stat` reports 69,214 `$mux`, 11,234 `$eq`, 3 `$memrd`, 3 `$memwr_v2`, and 146 memory bits in the parser hierarchy.

No resource-fit inference is possible. This is synthesis scalability/non-completion, not a demonstrated FPGA capacity failure.
